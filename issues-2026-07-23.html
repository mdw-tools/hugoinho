# File Severity Resolution Category Issue
1 topic_page_rendering_handler.go High Resolved Bug (doc mismatch) README previously said topics need 3 articles to render, but code filters at len == 1 (i.e., 2+). Documentation has been corrected to match the code.
2 path_loader.go / pipeline.go High Resolved Bug Errors during path loading are silently lost. PathLoader.Start() stores errors in this.err and Finalize() returns them, but Finalize() is never called (PathLoader is not wrapped by goListen()). Bad file paths are never surfaced.
3 hugoinho-dev/main.go High Resolved Bug (race condition) Concurrent requests race on output directory. os.RemoveAll(config.TargetRoot) + runner.Run() happen per-request with no locking. Two simultaneous requests will corrupt/erase each other's output. Fixed: added sync.Mutex to serialize build requests.
4 listener.go Medium Wontfix Design No pipeline short-circuit on error. When a handler sets article.Error, the article still flows through ALL remaining handlers. This is wasteful and can produce unexpected output (e.g., rendering a broken article).
5 stack_trace_error.go Medium Wontfix Code quality Every error is wrapped with a full stack trace. This makes logs extremely verbose and hard to read. Applied indiscriminately to all 30+ error paths. Consider using it only for unexpected/internal errors.
6 template_loader.go Medium Resolved Bug Template name collision in subdirectories. entry.Name() returns just the filename (e.g., home.tmpl). If two subdirectories both contain home.tmpl, the second silently overwrites the first. No path-based namespacing. Fixed: templateName() now uses filepath.Rel(this.folder, entry.Path) to namespace templates by their relative path. Top-level files keep their filename; subdirectory files are namespaced (e.g., components/header.tmpl).
7 cli_parser.go Medium Resolved Security No path traversal validation. Paths like ../../etc or ../secret were accepted without sanitization. A malicious config could write outside the target directory. Fixed: hasPathTraversal() now rejects any path containing .. components in TemplateDir, ContentRoot, or TargetRoot. Error messages sanitize .. to <traversal> to avoid leaking directory structure.
8 stack_trace_error.go Low Resolved Code quality Stack trace on user-input errors. Wrapping errors like “blank metadata title” or “duplicate slug” with stack traces is excessive noise. Fixed: removed StackTraceError() from all 43 call sites across 11 files. Deleted stack_trace_error.go. All errors now use plain fmt.Errorf() wrapping without stack traces.
9 listener.go Low Wontfix Design Handler result discarded when article has prior error. When article.Error != nil, handler.Handle() is skipped entirely. This means a later handler can’t recover or clean up from an earlier error.
10 metadata_parser.go Low Resolved Code quality Inconsistent error wrapping. Some errors used StackTraceError(), others used raw fmt.Errorf(). Fixed: unified all error handling to use plain fmt.Errorf() wrapping. StackTraceError() removed entirely. All 15 error paths across the codebase now follow the same pattern.
11 topic_page_rendering_handler.go Low Resolved Design Topics collected per-article but never deduplicated across pipeline. If an article has duplicate topics in its front-matter, parseTopics checks for duplicates, but the topics map in TopicPageRenderingHandler could accumulate duplicate entries. Fixed: Handle() now uses a seen map to skip duplicate topics within a single article, preventing the same article summary from being appended multiple times under the same topic.
12 GoldmarkMarkdownConverter Low Resolved Code quality Buffer not reset on error. Issue resolved by calling this.buffer.Reset() at the start of every Convert() call. Note: goldmark never returns an error for any input, so this is purely defensive programming — but the fix is correct and harmless.
13 Throughout Low Wontfix Style this receiver naming. The codebase consistently uses this as the receiver name instead of Go convention (p, m, or the struct initial). Makes the code look non-idiomatic to Go developers.
14 metadata_parser.go Low Wontfix UX draft: "" returns error rather than defaulting to false. Missing draft field could reasonably default to false instead of producing an error.
15 pipeline.go Low Wontfix Design No concurrency control. Each pipeline stage spawns a goroutine with no bounds. If the pipeline is extended with many stages, goroutine count grows linearly with pipeline length.
16 hugoinho-dev/main.go Low Wontfix Performance Full regeneration per HTTP request. The dev server regenerates the entire site on every page load (os.RemoveAll + full pipeline). Should cache or only regenerate changed files.
17 pipeline.go Low Wontfix Edge case No .gitignore or hidden file filtering. Any .md file in the content directory is processed, including hidden files (.hidden.md) or editor swap files.
